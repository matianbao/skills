# 圆桌会议 · 多专家交互式讨论系统

> 一个问题，多面镜子。不是为了达成共识，是为了看清全貌。

## 使用说明

**此 Skill 激活后，自动启动 Web 应用，不在终端中讨论。**

### 自动执行流程

1. 检查服务器是否已运行：`curl -s http://127.0.0.1:8000/api/experts >/dev/null 2>&1`
2. 如果未运行，后台启动（必须显式传递环境变量）：`cd ~/roundtable-app && ANTHROPIC_BASE_URL="$ANTHROPIC_BASE_URL" ANTHROPIC_AUTH_TOKEN="$ANTHROPIC_AUTH_TOKEN" ANTHROPIC_DEFAULT_SONNET_MODEL="$ANTHROPIC_DEFAULT_SONNET_MODEL" python3 server.py &>/tmp/roundtable-server.log &`
3. 等待服务就绪：`curl --retry 3 --retry-delay 1 -s http://127.0.0.1:8000/api/experts >/dev/null`
4. 打开浏览器：`open http://127.0.0.1:8000`
5. 告知用户："圆桌会议已在浏览器中打开，直接在网页上输入主题开始讨论。"

**不要在终端中进行讨论，所有交互都在网页上完成。**

---

### 网页功能说明

输入一个主题，系统自动匹配最相关的思维框架专家，各专家以角色扮演方式发言讨论。
用户可以追问、引导方向、指定专家深入展开。讨论结束后自动生成结构化会议纪要。

**已有专家库**：自动扫描 `.claude/skills/*-perspective/` 目录，所有已蒸馏的人物 Skill 均可参会。

---

## 执行流程

### Step 0: 读取配置

读取 `../_shared/user-config.json`，获取：

- `VAULT_PATH = paths.obsidian_vault`
- `ROUNDTABLE_DIR = {VAULT_PATH}/{roundtable.save_dir}`（默认 `Roundtable`）
- 如果 `ROUNDTABLE_DIR` 不存在，创建它

### Step 1: 专家匹配

1. 扫描 `.claude/skills/*-perspective/SKILL.md`，读取每个文件的 YAML frontmatter `description` 字段
2. 根据用户输入的主题，判断哪些专家的思维框架最能贡献有价值的视角
3. 选择 3-5 位专家（不超过5位，否则讨论太分散）

**匹配原则**：
- 不是选「知道这个话题的人」，而是选「能提供独特分析角度的人」
- 优先选择视角差异大的组合（如：技术派 + 商业派 + 风险派），避免同质化
- 如果主题明显偏向某个领域，可以减少到 3 位

**展示候选并确认**：

```
🏛️ 圆桌会议

🎯 主题: {用户输入的主题}

📋 建议参会专家:
1. {emoji} {专家名} — {此人能贡献的独特视角，一句话}
2. {emoji} {专家名} — {此人能贡献的独特视角，一句话}
3. {emoji} {专家名} — {此人能贡献的独特视角，一句话}

💡 你可以: 增加/移除专家、调整人数，或直接回车开始讨论
```

**专家 emoji 映射**（固定分配，保持一致性）：

|------|-------|
| elon-musk | 🚀 |
| munger | 📚 |
| taleb | 🦢 |
| feynman | 🔬 |
| paul-graham | ✍️ |
| naval | 🧘 |

| zhang-yiming | 📱 |

| ilya-sutskever | 🤖 |
| mrbeast | 🎬 |
| trump | 🏛️ |
| sun-yuchen | 💰 |

用户确认后进入 Step 2。

### Step 2: 加载专家上下文

对每位选中的专家：

1. 读取完整的 `SKILL.md` 文件
2. 提取关键信息供讨论使用：
   - 身份卡（角色定位）
   - 核心心智模型（分析工具）
   - 决策启发式（判断规则）
   - 表达DNA（语言风格）
   - 价值观与反模式（立场倾向）

**重要**：讨论中每位专家的发言必须严格遵循其 SKILL.md 中定义的心智模型和表达DNA。不是泛泛地「从XX角度」，而是真正运用其具体的分析框架。

### Step 3: 第一轮发言

每位专家针对主题给出 200-400 字的初始观点。

**发言规则**：
- 必须运用该专家 SKILL.md 中的至少 1 个心智模型
- 必须符合该专家的表达DNA（句式、词汇、节奏）
- 用第一人称「我」发言，完全进入角色
- 不需要每次都加免责声明，只在整场讨论开始前说一次

**发言格式**：

```
┌─ {emoji} {专家名} ─────────────────────────────
│
│  {发言内容，200-400字}
│
│  📌 运用框架: {所用的心智模型名称}
│
└──────────────────────────────────────────────
```

所有专家发言完毕后，提示用户：

```
──────────────────────────────────────
💬 第一轮发言结束。你可以:
  • 直接提问（所有专家回应）
  • @{专家名} 具体问题（指定专家回答）
  • 「让{A}和{B}辩论一下{话题}」
  • 「下一轮」— 各专家针对前面讨论继续发言
  • 「总结」— 结束讨论，生成会议纪要
──────────────────────────────────────
```

### Step 4: 交互式讨论

根据用户输入执行不同动作：

| 用户输入 | 动作 |
|---------|------|
| 直接提问 | 所有专家依次回应，每人 100-200 字 |
| `@专家名 问题` | 指定专家单独回答，200-400 字 |
| `让A和B辩论/讨论 X` | A先发言，B回应A，可多轮 |
| `下一轮` | 每位专家针对前面所有讨论内容发表新观点 |
| `总结` / `结束` | 进入 Step 5 生成会议纪要 |
| `加入 @新专家` | 动态加载新专家 SKILL.md，新专家先快速评论前面讨论 |
| `移除 @专家` | 该专家不再发言 |

**讨论质量规则**：
- 专家之间应该有真实的互动——引用、反驳、补充前面专家的观点
- 不要所有人都说「我同意」，要体现真实的思维差异
- 如果某位专家的框架确实不适用于当前子话题，可以说「这不是我擅长的领域」并简短带过
- 每轮讨论后都重复显示操作提示

**内部记录**：
在讨论进行中，维护一个内部讨论记录结构：

```
讨论记录 = {
  topic: "主题",
  participants: ["专家1", "专家2", ...],
  rounds: [
    {
      round_num: 1,
      title: "各方观点",
      speeches: [
        { speaker: "马斯克", emoji: "🚀", content: "...", framework: "渐近极限法" },
        ...
      ]
    },
    {
      round_num: 2,
      title: "用户追问: XXX",
      speeches: [...]
    }
  ]
}
```

### Step 5: 生成会议纪要

讨论结束后，生成结构化 Markdown 文件：

```markdown
---
date: {YYYY-MM-DD}
topic: {主题}
participants:
  - name: {专家名}
    emoji: {emoji}
    skill: {skill目录名}
  - ...
rounds: {总轮次数}
---

# 圆桌会议: {主题}

> 会议日期: {YYYY-MM-DD} | 参会: {emoji1}{名1} {emoji2}{名2} ... | 共 {N} 轮讨论

## 参会专家

| 专家 | 身份 | 核心视角 |
|------|------|---------|
| {emoji} {名} | {一句话身份} | {本次讨论中运用的主要框架} |

---

## 讨论记录

### 第一轮: 各方观点

#### {emoji} {专家名}

{发言内容}

> 📌 运用框架: {心智模型名称}

#### {emoji} {专家名}

{发言内容}

> 📌 运用框架: {心智模型名称}

---

### 第二轮: {本轮主题/用户追问}

#### {emoji} {专家名}

{发言内容}

---

## 会议纪要

### 共识

各方一致认同的观点：

1. {共识点1}（{提出者} + {附议者}）
2. {共识点2}

### 分歧

主要分歧及各方理由：

1. **{分歧主题}**
   - {emoji}{专家A}: {观点及理由}
   - {emoji}{专家B}: {反对观点及理由}

### 关键洞察

本次讨论中最有价值的观点：

1. 💡 {洞察1}（来自 {emoji}{专家名}，运用 {框架名}）
2. 💡 {洞察2}

### 行动建议

基于讨论综合得出的可操作建议：

- [ ] {建议1}
- [ ] {建议2}
- [ ] {建议3}
```

**保存路径**: `{ROUNDTABLE_DIR}/{YYYY-MM-DD}-{topic-slug}.md`

topic-slug 规则：取主题前20字，中文保留，空格替换为 `-`，去除特殊字符。

保存后告知用户文件路径，并提示可以运行 `/roundtable-web` 发布到网页。

## 讨论质量守则

1. **角色一致性** — 每位专家的用词、句式、分析方式必须匹配其 SKILL.md 中的表达DNA。读者应该仅从文字就能辨认出是哪位专家在说话。
2. **框架驱动** — 不是泛泛而谈，每次发言都要明确运用某个心智模型或决策启发式来分析问题。
3. **真实分歧** — 不同专家之间应该有真实的观点冲突。如果所有人都同意，要么主题太简单，要么没有真正进入角色。
4. **互动性** — 后发言的专家应该引用、回应、反驳前面专家的观点，而不是各说各话。
5. **诚实边界** — 如果某个问题超出专家的能力边界（如让费曼分析商业模式），该专家应该承认并简短带过，不要强行分析。

## 特殊场景

### 用户没有指定主题
引导用户提供主题：「你想让专家们讨论什么话题？可以是一个问题、一个决策、一个趋势、一个争议...」

### 只有1-2位专家匹配
如果主题太窄只匹配到1-2位专家，告知用户并建议：
- 扩大主题范围
- 手动指定额外专家
- 或者直接用单个专家的 perspective skill（不需要圆桌）

### 讨论跑偏
如果用户的追问偏离原始主题太远，提醒一次：「当前讨论已偏离原始主题 '{topic}'，是否继续当前方向，还是拉回来？」

### 超长讨论
超过5轮后，主动建议：「已经讨论了{N}轮，是否需要总结？继续讨论也可以。」
